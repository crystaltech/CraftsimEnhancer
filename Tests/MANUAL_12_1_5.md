# 12.1.5 in-game checks — 1.7.0

Install only the `CraftSimEnhancer` folder from `zip/CraftSimEnhancer-v1.7.0-addon-only.zip`, beside CraftSim and Auctionator. Automated integration was checked against CraftSim 27.0.7. Record your actual versions if using a newer release. Enable `/console scriptErrors 1` or use BugSack/BugGrabber. Keep the first Lua error if one occurs.

1. **Startup.** Run `/cse status`. Expect Enhancer 1.7.0, WoW interface 120105, and enabled modules initialized. Untested-version warnings remain expected. Open and close professions, the Auction House, and a merchant; confirm controls appear once and no errors occur.
2. **Decor and reduced quantities.** In Recon's Recipes view, select a profession and check its expansion-labeled House Decor groups. Check an available Classic decor recipe, a newly added older-expansion decor recipe, a Dragonflight recipe with ranked reagents, and a Midnight recipe. For recipes you can craft, compare CraftSim's ingredients and quantities against Blizzard's profession window. With **Update Last Crafting Cost DB** enabled, rerun CraftSim Recipe Scan, then recreate the shopping list for one craft. It must use the current quantities, not the pre-patch vendor plan.
3. **Recon scopes and prices.** Scan a few recipes under Products + reagents, Crafted products, and Required reagents. Bound lumber and vendor supplies must not generate AH queries. Pickup-bound decor must have no product query, but its tradeable materials must remain selectable in reagent modes. Cancel and restart a scan. Push overrides and confirm CraftSim refreshes prices, including separate material ranks. Export an Unpriced report if items are missing; empty listings must be distinguished from scan failures.
4. **Break-even tooltips.** Hover a crafted output whose CraftSim cost has just been saved. Verify its CSE break-even tooltip uses the updated cost and correct rank. If you have an unlisted output, confirm the estimate uses saved cost divided by 0.95; absent cost must not produce an invented price. Note any lumber override you have configured when comparing costs.
5. **Vendor purchasing.** Create a fresh mixed AH/vendor shopping list. Confirm vendor supplies move to Vendor Materials once, with correct quantities and no duplicate notice. Buy a small quantity at the correct merchant. The plan must decrease only after the items arrive in bags; a partial purchase must leave the remainder. Reload with an unfinished plan and confirm it persists. Confirm unrelated merchants do not offer to buy unavailable supplies. If practical, also check a failed purchase/full-bag case without losing the outstanding plan.
6. **Shopping-list automation.** With CraftSim automatic shopping lists enabled, finish a queue operation and check one list publication/vendor split. Disable automation and repeat: no automatic publication. Manual list creation must still publish and split vendor supplies. Restore your preferred setting afterward.
7. **Developer export and persistence.** Follow [the export instructions](../docs/DEV_EXPORT.md). Keep the same profession open until the completion message, then `/reload`. Confirm `/cse dev status` reports a saved capture and the account SavedVariables file contains `CraftSimEnhancerDevDB`. Repeat for other professions/characters and expansion views where needed. Missing or uncached data must be reported, not hidden. During another profession dump, switch professions to check cancellation; the earlier completed capture must survive. Then close professions and run `/cse dev catalog`: it should query the generated recipe IDs without a learned/open profession and save a separate catalog capture. Check the reported schematic/incomplete counts and confirm earlier captures survive.

8. **Expansion views and migration.** Start with existing saved selections. Confirm imported recipes begin unselected. In Recipes view expect Profession → Expansion → Category → Recipe, with recent expansions first. Select one Classic recipe and one Midnight recipe sharing a reagent where possible. Switch expansion views and toggle either recipe: hidden selections must survive, and the shared reagent remains selected while either recipe needs it. Check Individual Items overrides, then select/deselect the visible view. Scan preparation must include selected recipes across expansions; the view filter must not silently restrict the scan. Disabled catalog-only entries should explain why they cannot scan. Check a bound-output decor recipe retains selectable tradeable materials.
9. **Responsiveness and cancellation.** Run `/cse dev perf` before opening Recon and after the first view loads. Select all nine professions, use All expansions, expand/collapse groups, scroll rapidly, and switch expansion filters while preparation is running. Check text, scroll positions, checkboxes, tooltips, and row reuse for visual glitches. Reopen a warm view and compare timing/cache hits. Try selecting many recipes, starting/stopping during preparation, and closing the AH during preparation. No late scan or Lua error should occur. Run `/cse dev perf` again and report timing, row counts, memory and any perceived frame hitch. Compare normal play with Recon closed; catalog jobs should stop when finished. The 2 ms preparation budget is a target; Lua garbage collection and engine calls can exceed it.
10. **Large export cancellation.** With no professions open run `/cse dev catalog`, cancel midway, and confirm earlier captures survive. Repeat to completion, then `/reload`. Expect 10,621 attempted numeric IDs across the combined catalog; incomplete results remain explicit. Cancellation during the final snapshot stage must also preserve earlier captures. Clear exports after collecting the evidence you need.

11. **Availability.** On a fresh login, expect Unchecked until opening your own professions. Open a learned profession, let it load, and check Learned/Unlearned labels against Blizzard's learned state, including another era if needed. Browse All, Learned, Unlearned and Unchecked in both Recipes and Individual Items. Unlearned rows should be dimmed yet selectable; filters and bulk actions must preserve off-screen selections. Open a linked/guild/NPC profession if available and confirm it does not seed your cache. Learn a recipe and confirm its state updates. Enable **Scan learned recipes only** in Availability: the button gains an asterisk and scan target counts exclude unlearned/unchecked sources even if individually overridden, while shared materials contributed by learned recipes remain. Disable it and confirm choices return. Test closing/switching professions during loading, and forgetting/relearning a profession only if convenient. Run `/cse dev perf` before/after repeated browsing; scrolling must not trigger availability refreshes. After logging out/in, states start Unchecked again.

12. **Unlisted ranks.** Scan equipment with listings at only some quality ranks. Missing classified ranks should say **Rank not listed** and explain that other ranks are listed; ordinary item-level variants should say **Variant not listed**. An empty search remains **No auctions**. Unresolved ranks and query failures must retain their distinct reasons. Exact-rank prices must not be copied from other ranks. Push Overrides with a saved CraftSim cost and confirm absent ranks still receive the established break-even estimate, capped by a real better-rank price where available.

Report client build, Enhancer/CraftSim/Auctionator versions, which steps passed or were skipped, the first Lua error, and the SavedVariables export. A profession dump supplements these behavior checks; it cannot establish correct merchant transactions or AH server responses by itself.

Only advance the tested-version markers after the relevant in-game checks pass.
